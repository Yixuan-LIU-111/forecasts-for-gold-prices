# 前端页面结构说明与功能模块划分方案

> 对应需求文档：`/docs/项目方案V1.0.md`
> 交付物：`frontend/dashboard.html`（单文件、可直接双击打开，无需构建）
> 设计方向：编辑式财经终端（暖羊皮纸底 · 深咖导航 · 古铜金强调 · 衬线标题），图表引擎与方案一致使用 Plotly。

---

## 1. 总体布局（两区职责分明）

页面采用 **「左导航栏 + 右工作画布」** 的固定双区布局，从外壳层面就划分出两类职责：

| 区域 | 职责 | 边界手段 |
|------|------|---------|
| 左侧导航栏（深咖色块） | 一级功能模块的切换与全局状态 | 独立色块 + 固定定位，与内容区在视觉上完全隔离 |
| 右侧工作画布（浅色） | 当前模块的详细内容 | 顶部标题栏 + 行情滚动条 + 可滚动内容区 |

- **导航栏**列出 5 个一级功能模块（仪表盘 / 新闻中心 / 回测分析 / 准确率统计 / 系统设置），每项有清晰的模块名与图标，一眼可辨所属功能域。
- **画布顶栏**实时显示当前模块标题、所属模块面包屑、运行状态与时钟，避免用户迷失。
- 模块之间为 **整页切换**（非同屏混排），保证每个模块独占工作区、职责互不干扰。

---

## 2. 一级功能模块划分（5 个）

严格依据需求文档《项目方案V1.0》第 3 章功能清单与第 10.2 节仪表盘导航骨架划分：

| # | 模块 | 对应功能 | 核心职责 | 内容分区（区内子带） |
|---|------|---------|----------|----------------------|
| 1 | **仪表盘** | 聚合行情 / 信号 / 新闻 / 因子 / 绩效输出 | 实时监测中枢，一眼掌握全局 | ①实时行情 ②信号决策 ③资讯情绪 ④因子监控 ⑤绩效速览 |
| 2 | **新闻中心** | 新闻采集 · 情感分析 · 鹰鸽判定 | 新闻输入与语义理解 | ①采集状态 ②新闻流+情感分析 ③鹰鸽指数 |
| 3 | **回测分析** | 历史回测引擎 | 策略历史验证 | ①回测配置 ②绩效指标 ③收益曲线 |
| 4 | **准确率统计** | 模型准确率评估 | 模型表现评估 | ①滚动窗口准确率 ②按方向分类 ③与基准对比 |
| 5 | **系统设置** | 数据源 · 模型 · 信号参数 · 系统监控 | 配置与运维 | ①数据源 ②模型 ③信号参数 ④系统监控 |

**划分依据**：需求文档将功能按"数据层 / 模型层 / 应用层"分组；第 10.2 节仪表盘 ASCII 图已明确给出"仪表盘 / 新闻 / 回测 / 统计 / 设置"五个导航项。本方案据此把分散的功能收口为 5 个边界清晰的一级模块，每个模块只承载同域职责，避免功能交叉。

> 说明：仪表盘原包含"历史准确率统计图表"与"回测收益曲线"，但这两项在导航中另有独立模块。为避免重复，仪表盘仅保留 **⑤绩效速览** 作为缩略概览，点击对应模块查看完整内容——既忠于需求，又维持模块边界。

## 3. 模块内部子区域划分（以仪表盘为例）

仪表盘是聚合度最高的模块，内部用 **「横向分区带」** 进一步切分，每条带由 **编号标签 + 金色渐变分隔线 + 留白** 三件套明确边界，杜绝"卡片套卡片"：

```
┌─────────────────────────────────────────────┐
│ ① 实时行情        [批发市场数据采集]          │  ← 编号 + 金色渐变线
│   价格走势图 | 当前报价 + 关联指标            │
├─────────────────────────────────────────────┤
│ ② 信号决策        [信号生成 + 多空评分]       │
│   信号主卡(可展开归因) | 黄金多空评分          │
├─────────────────────────────────────────────┤
│ ③ 资讯情绪        [新闻 + 情感分析]           │
│   新闻流(情感标签) | 情感分布图                │
├─────────────────────────────────────────────┤
│ ④ 因子监控        [实时因子面板]              │
│   DXY | TIPS | VIX | 情感均值  (四宫格瓦片)    │
├─────────────────────────────────────────────┤
│ ⑤ 绩效速览        [准确率 + 权益曲线概览]     │
│   滚动准确率(缩略) | 权益曲线(缩略)           │
└─────────────────────────────────────────────┘
```

每个子带的元素职责：

- **① 实时行情**：后端从新浪财经等公开行情源采集的 XAUUSD 分钟级价格 → Plotly 折线图 + 关联指标卡。
- **② 信号决策**：信号生成器输出（方向/概率/强度/仓位）+ 黄金多空评分；`<details>` 折叠"信号归因与引用溯源"实现渐进式披露，不挤占主视觉。
- **③ 资讯情绪**：新闻列表（🔴利多/🟢利空/⚪中性）+ 滚动情感分布。
- **④ 因子监控**：DXY / TIPS / VIX / 情感均值 四宫格，实时因子面板。
- **⑤ 绩效速览**：缩略准确率与权益曲线，引导至完整模块。

## 4. 视觉分隔手段汇总

为满足"模块边界清晰、职责分明"的硬性要求，页面综合运用四类分隔手段：

1. **布局分区**：左导航（模块切换）与右画布（内容）物理隔离；模块间整页切换。
2. **标题层级**：`band-num`（编号）+ `band-title`（衬线标题）+ `band-meta`（模块标签）三级标题，层级可一眼读清。
3. **视觉分隔线**：每条分区带下方一条 `金色渐变 → 透明` 的 2px 分隔线，强化区域边界；卡片/瓦片用 1px 发丝边而非重阴影。
4. **色彩语义**：品牌金仅用于强调（≤10% 视觉权重）；**涨 / 看多 = 红、跌 / 看空 = 绿**，遵循国内金融用户视觉习惯（与文档原"绿=利多"国际惯例相反，已按用户要求覆盖）；所有方向信息同时配文字标签，照顾色觉差异。系统健康/正常类状态（运行正常、已连接）使用独立绿色，不与涨跌语义混淆。

## 5. 数据/接口映射（已联调打通 ✅）

> 状态：**后端联调已完成**（2026-08-06）。页面已从静态原型切换为真实接口调用，所有数值均来自后端 SQLite 数据库（`data/gold_predictor.db`），经 headless DOM 联调测试 **0 运行时错误**。

前端统一请求封装 `api(path)` 解析后端 `{code,message,data}` 信封；跨域已在后端放开（CORS `allow_origins=["*"]`），demo 模式无鉴权。

| 前端视图 / 分区 | 真实接口（后端 `app/api/*.py`） | HTTP | 状态 |
|------|---------|------|------|
| 仪表盘 ① 实时行情 | `/api/v1/market/price?range_hours=4h` | GET | ✅ |
| 仪表盘 ② 信号决策 | `/api/v1/signals/latest` | GET | ✅ |
| 仪表盘 ③ 资讯情绪 | `/api/v1/news?limit=20` | GET | ✅ |
| 仪表盘 ④ 因子监控 | `/api/v1/factors` | GET | ✅ |
| 仪表盘 ⑤ 绩效速览 | `/api/v1/stats/accuracy?window=7d` + `/api/v1/backtest/results` | GET | ✅ |
| 新闻中心（采集状态/流/鹰鸽）| `/api/v1/news?limit=50` + `/api/v1/hawk-dove/events?days=30` | GET | ✅ |
| 回测分析（指标/曲线）| `/api/v1/backtest/results` | GET | ✅ |
| 回测分析（运行回测·写库）| `/api/v1/backtest/run` | POST | ✅ |
| 准确率统计 | `/api/v1/stats/accuracy?window=30d` | GET | ✅ |
| 系统设置（数据源列表）| `/api/v1/system/data-sources` | GET | ✅ |
| 系统设置（监控/模型信息）| `/api/v1/system/status`（返回 `db_type` / `model_info`）| GET | ✅ |

**字段映射要点**：
- 后端涨跌语义采用国际惯例（red=利空 / green=利多），前端经 `inv()` 翻转为本项目约定的国内习惯（红=涨/利多、绿=跌/利空），已通过联调验证（DXY 红→前端绿"利空黄金"，TIPS 绿→前端红"利多黄金"）。
- 信号方向 `direction_en`：bullish→红(涨)、bearish→绿(跌)、neutral→灰。
- 回测 `summary` 已包含 `benchmark_return_pct`（基准收益率，由真实价格序列 `p1/p0-1` 计算）与 `data_mode`（real/synthetic）字段；`equity_curve` 使用 `time/strategy/benchmark` 键。

详细联调结论见 `docs/联调测试结论.md`。
