| 维度 | V1.0 | V2.0（本版）| 变更依据 |

## 0.1 核心约束（不可变更，最高优先级）

本方案受用户两项**硬性约束**锁定，任何设计、开发、文档均不得违反或擅自调整：

### 约束一 · 配色方案：涨红跌绿（以现有实现为准）

- 配色逻辑固定为「**涨 / 看多 / 利多 = 红，跌 / 看空 / 利空 = 绿**」，符合国内金融用户习惯。
- **唯一标准来源为已落地的 `frontend/dashboard.html` 实现**，其语义色定义为：
  - `--bull: oklch(54% 0.150 25)` —— 涨 / 看多 = 红
  - `--bear: oklch(52% 0.120 155)` —— 跌 / 看空 = 绿
- **禁止擅自更改任何颜色定义或取值**；所有界面、组件、样式文件（含 `app/dashboard/` 下的 `config.py`、`utils/css.py`、`utils/helpers.py`）的配色必须与上述实现保持一致。
- `app/dashboard/` 当前为「涨绿跌红」（与标准相反），须在 Demo 联调前对齐为涨红跌绿——**仅调整语义映射，颜色取值保持不变**（详见 §3.6、§5.2 R12）。

### 约束二 · 预测窗口：固定 30 分钟

- 预测窗口**固定为未来 30 分钟**，是项目的核心特色，**不得调整为其他时间范围**（如日频、T+5 等）。
- 所有功能模块、数据展示、接口设计、参数命名与逻辑实现均须围绕 30 分钟窗口展开；相关参数须显式体现此固定窗口，命名约定：
  - `HORIZON_MINUTES = 30`
  - `PREDICT_WINDOW = "30min"`
  - 信号 / 行情 / 接口字段须带 `30min` 或 `30_min` 语义标记。
- V1.0 原要求的「分钟级采集、预测未来 30 分钟」 hereby **恢复为不可协商的核心定义**；本版此前临时的「日频」收敛方案作废（见 §5.2 R2 / R7 数据工程处置）。

## 第 1 章 项目背景与目标

### 1.1 项目背景

黄金兼具商品、货币、避险资产、通胀对冲等多重属性，价格受美元指数、实际利率、地缘政治、央行购金、通胀预期等复杂因素驱动。传统量化模型依赖历史价格和技术指标，对美联储决议、地缘冲突等突发事件反应滞后，且难以理解「鹰派降息」「避险情绪升温」等复合金融语境。

大语言模型（LLM）的成熟为金融文本理解提供了新路径。LLM 能实时解析新闻、官员讲话、地缘事件，提取对黄金的利多/利空程度。本项目将 LLM 情感分析与传统时序预测模型融合，构建**未来 30 分钟**黄金价格方向预测系统，并以**可运行 Demo** 验证「LLM 情感 + 量化模型」的技术可行性与工程链路完整性。

### 1.2 项目目标（V2.0 Demo 阶段）

| 维度 | V2.0 目标 | 与 V1.0 差异 |
|------|----------|-------------|
| 核心目标 | 黄金价格（XAU/USD）**未来 30 分钟**方向预测，产出可运行 Demo | 恢复 V1.0 的 30 分钟核心窗口（用户约束，不可调为日频）|
| 工程目标 | 端到端链路跑通：数据 → 情感 → 模型 → 信号 → 仪表盘全为真实数据 | 取消 PG/Docker 常驻依赖 |
| 模型验证 | 完成「LLM 情感特征入模」消融，明确核心假设是否成立 | 新增，原为空白 |
| 信号延迟 | 模型推理 < 3 秒；情感分析异步/缓存，不阻塞主链路 | 口径放宽（R8）|
| 部署环境 | 个人笔记本本地运行（8GB+ 内存），单命令启动 | 取消 Docker 一键启动 |
| 交付周期 | ≈11 自然日（2 人并行，≈13.5 人天）| 由 14 天/43.5 人天下调，因 30 分钟数据工程略增 |
| 配色标准 | **涨红跌绿**，以 `frontend/dashboard.html` 现有实现为唯一标准 | 用户约束（覆盖 DP-6）|

**非目标说明**：本 Demo 非生产级系统，不追求高并发、高可用（99.99%+）与实时交易接入；**方向准确率不作为 Demo 验收门槛**，其效果优化作为独立研究议题后置（见 §5.2 R1、§4.4）。核心价值在于验证「30 分钟窗口 + LLM 情感融合」的技术可行性与工程链路完整性。

### 1.3 项目定位与差异化

| 差异化维度 | 策略 | 竞品空白 |
|-----------|------|---------|
| LLM + 量化融合 | LLM 情感分数作为量化模型**特征输入**（非独立信号）| 多数产品仅侧重单一技术路线 |
| 黄金垂直聚焦 | 专注黄金单一品种，做深做透 | 竞品覆盖全市场，缺乏品种深度 |
| **30 分钟极短周期** | **固定未来 30 分钟方向预测，国内涨红跌绿配色** | 竞品多为日/周级，且多为西方涨绿跌红 |
| 可解释性优先 | 每条信号附带新闻来源 + 因子贡献度 | 黑盒评分系统缺乏透明度 |
| 渐进式演进 | Demo 单体可平滑升级到生产化微服务 | — |

> 注：**30 分钟预测 + 涨红跌绿配色**为项目**固定核心窗口与视觉标准**（用户硬约束），Demo 与生产化阶段均围绕 30 分钟展开，不做日频等其他范围调整。分钟级历史长度（R2）仅作为数据工程风险单独处置（见 §5.2）。

### 2.2 数据层功能设计

- **价格与因子**：复用现有 6+1 个独立爬虫（dxy / vix / dfii10 / gpr / epu / fred / investing_calendar），输出 JSONL；黄金价格以 **30 分钟 K 线**为预测对象。Demo 阶段采用可获取 30 分钟历史的数据源（如新浪 / CBOE 30 分钟 K 线爬虫，或替代 intraday 源），`gold_prediction_model/data_loader.py` 现有日线管道作为降级参考（详见 R2 / R7）。
- **新闻**：Playwright 抓 4 家官网，支持详情页摘要；落本地 JSONL。
- **聚合契约**：写聚合脚本，将爬虫输出与 `data/` 已有快照合成为 `demo_data/*.json`（信号 / 行情 / 新闻 / 回测 / 鹰鸽），作为前后端唯一数据交换格式（即 V1.0 定义的 API 响应契约的本地实现）。其中行情字段须体现 30 分钟粒度（如 `interval: "30min"`）。
- **去重**：新闻按 URL 精确去重（Demo 阶段以文件级去重为主，数据库唯一约束留待生产化）。

### 2.3 模型层功能设计

- **LLM 情感分析（F04）**：`news_scraper_llm/analyzer.py` 已实现三级容错（结构化输出 → 文本解析 → 中性降级）。V2.0 需补齐：Few-shot 示例、黄金领域同义词库、URL 去重缓存、每日成本上限熔断。
- **鹰鸽指数（F05）**：V2.0 新增 `app/core/hawk_dove.py`，将现有 UI/demo 中的鹰鸽数据落地为真实提取逻辑。
- **时序预测（F07）**：`gold_prediction_model/` 已实现 LightGBM + XGBoost + 0.6/0.4 集成 + Purge + Walk-Forward。**V2.0 固定为 30 分钟窗口（`HORIZON_MINUTES=30`）**，并将情感/鹰鸽特征**真正入模**（原为占位空接口），通过消融验证增量。

### 2.4 应用层功能设计

- **信号生成器（F08）**：V2.0 新增纯函数式 `app/core/signal_generator.py`，实现 V1.0 §10.1 规则表（方向/仓位）、防抖（3 次反转→观望、VIX>40 降档、置信度<0.55→观望）、多空评分公式、信号归因（因子贡献 + 新闻引用 + 双模型概率）。信号方向标签须与涨红跌绿语义一致（涨=红 / 跌=绿）。
- **仪表盘（F09）**：`app/dashboard/` 现有 UI 完整（4 页签 9 组件）。V2.0 将其 `api/client.py` 由读静态 demo 改为读真实本地 JSON / 直调核心函数；**配色统一为涨红跌绿（以 `frontend/dashboard.html` 现有实现为唯一标准，不改变任何颜色取值）**；补齐错误态与系统状态真实指标。
- **回测与统计（F10/F11）**：演示用简化回测（可后置），准确率统计基于 `signals` 本地记录（30 分钟信号）。

## 第 3 章 技术架构设计

### 3.1 总体架构（Demo 单体版）

```
┌──────────────────────────────────────────────────────────┐
│                     Streamlit 仪表盘                        │
│  概览 / 实时行情 / 回测分析 / 新闻动态  (app/dashboard/)     │
│  配色：涨红跌绿（以 frontend/dashboard.html 为准）          │
└───────────────┬──────────────────────────────────────────┘
                │ 直调 / 读本地 JSON (demo_data/*.json)
┌───────────────┴──────────────────────────────────────────┐
│                  核心逻辑层 (app/core/)                     │
│  signal_generator ● predictor ● sentiment ● hawk_dove      │
│  + imports.py 桥接层（importlib 加载模型/爬虫，规避冲突） │
└───┬───────────────┬──────────────────┬────────────────────┘
    │               │                  │
┌───┴───┐   ┌───────┴───────┐   ┌──────┴──────────────┐
│ 模型   │   │ 新闻爬虫       │   │ 因子爬虫(6+1)       │
│ artifacts│  │ Playwright×4  │   │ 新浪/CBOE 30分钟K线  │
└───────┘   └───────────────┘   └─────────────────────┘
                │                   │
         ┌──────┴───────────────────┴───────┐
         │   本地数据契约 demo_data/*.json     │  ← 前后端唯一交换格式
         │   (signals/market/news/backtest/hd) │  ← 行情字段 interval="30min"
         └────────────────────────────────────┘
```

**与 V1.0 的区别**：取消 FastAPI 独立服务进程、PostgreSQL、Docker、APScheduler。所有逻辑在单个 Python 进程（Streamlit 运行时）内完成，数据以本地 JSON 文件闭环，显著降低 Demo 工程成本与启动门槛。**30 分钟预测窗口与涨红跌绿配色为不可变更约束（§0.1）。**

### 3.2 数据流架构

```
[因子爬虫/新闻爬虫]─产出 JSONL─┐
[30分钟 XAU/USD K线]──────────┼─→ 聚合脚本 ─→ demo_data/*.json (interval="30min")
[LLM 情感分析]────────────────┘        (契约合成)
                                      │
                      ┌───────────────┴───────────────┐
                      │ Streamlit 仪表盘 直接读取/渲染   │
                      │ 或 核心层 predictor→signal→写入  │
                      └─────────────────────────────────┘
```

### 3.3 模块划分与接口契约

| 模块 | 文件 | 职责 | 接口形态 |
|------|------|------|---------|
| 入口 | `app/dashboard/app.py` | Streamlit 仪表盘 | 直调核心层 / 读 JSON |
| 信号 | `app/core/signal_generator.py` | 规则 + 评分 + 归因 | `generate_signal(features, model_out) -> Signal` |
| 预测 | `app/core/predictor.py` | 模型封装（**30 分钟**）| `Predictor.predict(features) -> float`（窗口 `HORIZON_MINUTES=30`）|
| 情感 | `app/core/sentiment.py` | LLM 分析封装 | `analyze(news) -> SentimentResult` |
| 鹰鸽 | `app/core/hawk_dove.py` | 鹰鸽提取 | `extract(text) -> float` |

| 数据契约 | `demo_data/*.json` | 前后端交换格式 | 即 V1.0 §11.2 响应契约的本地实现（行情含 `interval:"30min"`）|

### 3.5 模型设计（固定 30 分钟窗口）

- **目标变量**：未来 30 分钟收盘价相对当前涨幅 > 0 记为「涨」，否则「跌」；参数固定 `HORIZON_MINUTES = 30`、`PREDICT_WINDOW = "30min"`。
- **特征工程**：
  - 价格序列：`return`、`volatility`、`MA` 偏离等（**30 分钟 rolling**）；
  - 情感特征：`sentiment_mean_30` / `sentiment_max_30`（**V2.0 真正入模**，原为空接口）；
  - 政策特征：`hawkish_change`（**V2.0 真正入模**）；
  - 市场特征：DXY / VIX / TIPS / GPR / EPU 的 **30 分钟**值（`ffill` 对齐，保持无前视偏差）。
- **双模型集成**：LightGBM + XGBoost，加权 `p = 0.6·p_lgb + 0.4·p_xgb`（与 V1.0 §9.4 一致）。
- **防泄露**：沿用已实现 Purge + Walk-Forward，并针对 30 分钟窗口重校 purge 长度。
- **情感特征消融（P0 关键）**：同一份 **30 分钟**数据，分别训练「含情感特征」与「不含情感特征」两版模型，对比 AUC / 准确率。若增量显著（AUC 提升 > 0.02），进入模型精调；若无增量（AUC < 0.53），Demo 照常跑通，模型效果列为独立研究议题，并在仪表盘明确标注「信号为演示用途」。
