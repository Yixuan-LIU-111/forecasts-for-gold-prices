## 0. 总体结论

仓库当前形态为「两头厚、中间空」——前端仪表盘与离线模型实验已有体量，但方案中作为系统骨架的 **PostgreSQL 存储层、统一数据采集层、信号持久化** 全部为 0 行代码。全仓检索 `postgres` / `sqlalchemy` / `psycopg2` 均无命中，所有数据散落在 `data/` 的 JSONL / CSV / JSON 文件。

摘要错配 #3 直接点明：**存储介质从方案要求的「PostgreSQL 5 张表」错配为「散落文件」**，这是所有落库工作的根因。

## 3. 数据采集与落库（market_data / news / 去重）

### 3.1 B-3｜`DataCollector` 抽象基类
- **涉及文件**：`app/core/data_collector.py`
- **预期实现**：对齐方案 §11.1 接口签名，作为所有采集器的统一基类
- **优先级**：P0
- **依赖**：A-3（包结构规整）

### 3.2 B-4｜`YFinanceCollector` 分钟级价格 → `market_data`
- **涉及表**：`market_data`
- **预期实现**：采集 `GC=F` / `DX-Y.NYB` / `^VIX` / `^IRX` 的**分钟级**数据写入 `market_data`
- **注意**：`GC=F` 为期货，与现货 XAU/USD 有基差（风险 R7），须在文档说明代理关系
- **优先级**：P0
- **依赖**：B-1、B-3、D-2（数据源路线定调）
- **关联错配**：差距表 #15（数据源错配，无 XAU/USD 采集器）、#16（频率错配，现为日频）

### 3.3 B-5｜新闻采集封装为 `NewsCollector` → `news` 表 ✅ 已实现
- **涉及文件**：`app/core/data_collector.py`、`news_scraper_llm/storage.py`
- **涉及表**：`news`
- **预期实现**：将现有 `news_scraper_llm` 封装，结果写入 `news` 表（当前 `storage.py` 只写 JSON/CSV，现状梳理 B 项「落库 ❌ 缺失」）
- **已实现**：`app/core/news_collector.py` → `NewsAPICollector(DataCollector)`，复用 `news_scraper_llm` 的 `ScrapingEngine` + 4 站点抓取器，`store()` 写入 `news` 表；`published_at` 解析容错（dateutil，缺失回退 scraped_at / now）
- **优先级**：P0
- **依赖**：B-1、B-3、D-3（新闻源定调）

### 3.4 B-6｜新闻去重（URL + 标题相似度 > 0.8） ✅ 已实现
- **涉及表**：`news`（URL 唯一约束 + 相似度去重）
- **预期实现**：URL 精确匹配 + 标题相似度 > 0.8（difflib / rapidfuzz）去重，避免重复入库
- **已实现**：`news_collector.py` 两层去重——URL 精确匹配（先查后插，幂等）+ 标题相似度 > 0.8（rapidfuzz，近 30 天窗口比对，回退 difflib）；`store()` 返回 `{inserted, skipped_url, skipped_title, links}` 供下游情感关联
- **优先级**：P0
- **依赖**：B-5
- **关联**：差距表 #18

### 3.5 B-7｜存量 6 个 scraper 接入统一接口 + 写库 ✅ 已实现
- **涉及文件**：`*_scraper/`、`app/core/factor_collectors.py`
- **涉及表**：数值因子 → `market_data`（DXY / VIX / TIPS10Y / GPR / EPU）；财经日历 → `economic_calendar`
- **预期实现**：将现有 6+1 个独立 CLI 爬虫（现输出 JSONL、不入库，现状梳理 D 项）接入统一接口并写库
- **已实现**：`app/core/factor_collectors.py` 将 dxy / vix / dfii10(TIPS) / gpr / epu / investing_calendar 封装为 `DataCollector` 子类；数值因子经共享 `store_market_data()` 按 `(timestamp, symbol)` 去重 upsert 入 `market_data`，TIPS/EPU 支持 `recent_data` 历史回填；日历事件经 `CalendarCollector.store()` 按 `(event_date, currency, event)` 去重入 `economic_calendar`；`collect_all_factors(db)` 一键跑全量（单源失败隔离）。各 scraper 用「隔离 sys.path 加载」解决裸名模块（config/scraper）跨爬虫冲突
- **优先级**：**P1**
- **依赖**：A-4（顶层模块名冲突治理）、B-1、B-3
- **说明**：fred_scraper 为空桩（main/scraper 均 1 行）已跳过；VIX 采集依赖 Playwright（无头浏览器）

- **涉及文件**：`app/core/signal_generator.py`

- **预期实现**：信号生成后每 5 分钟写入一条，含完整因子归因与新闻引用
- **已实现**：`app/core/signal_generator.py` → `generate_signal(db)` 取最新市场因子（DXY/VIX/TIPS10Y/GPR/EPU/GC=F）+ 近期情感均值，透明规则打分（6 因子加权，`_build_factors` 纯函数可测），生成 `Signals` 行（direction/probability/strength/position + factors/news_refs JSONB）并持久化；`latest_signal(db)` 供前端

- **说明**：参考实现 forecasts-for-gold-prices-main 依赖 ML 预测器（WeightedPredictor/feature_engineer），本工程未含该模型，暂用规则打分保证 E-3 落库链路独立可跑；后续接入模型只需替换 `_build_factors` / 概率来源

### 7.2 E-11｜回测结果落库 `backtest_results` 表 ✅ 已实现
- **涉及文件**：`app/core/backtest.py`（逻辑内置，无需依赖旧 `app/api/backtest.py`）
- **涉及表**：`backtest_results`（run_id UUID + JSONB metrics + JSONB trades）
- **预期实现**：`/api/backtest/run` 触发回测后，结果落库
- **已实现**：`app/core/backtest.py` → `run_backtest(db, params)` 向量化模拟（价格取 `market_data.symbol=GC=F`、信号取 `signals` 表），结果落库 `backtest_results`（metrics JSONB 含 summary/accuracy/equity_curve/pnl_distribution，trades JSONB 含 trade_details）；`_simulate()` 纯函数；无数据走合成兜底；`get_latest_backtest(db)` 读最近一次
- **优先级**：**P1**
- **依赖**：B-1、E-3（信号来源）
- **对齐说明**：落入 `backtest_results.metrics/trades` 两个 JSONB 列（§8.2），而非参考实现的多个独立 JSONB 列，保持与落库清单一致

## 9. 优先级与依赖关系总览

### 9.1 按优先级汇总

| 优先级 | 落库相关项 |
|---|---|
| **P0（端到端跑通必需）** | PostgreSQL/SQLAlchemy 引入、B-1、B-2、B-3、B-4、B-5、B-6、B-8、C-1、C-2、E-3、A-6 —— **均已实现 ✅** |
| **P1（验收标准必需）** | B-7、B-9、C-6、E-11 —— **均已实现 ✅** |
| 隐性前提 | 数据层全部依赖「PostgreSQL + SQLAlchemy」存在；A-4（顶层模块名冲突治理）必须先于 B-7 完成 |

### 9.2 关键依赖链（落库视角）

```
PostgreSQL / SQLAlchemy (B-1, B-2)
   ├─→ B-4 价格采集            → market_data
   ├─→ B-5 + B-6 新闻采集去重   → news
   │       └─→ C-1 情感落库     → sentiment（FK news_id）
   │              └─→ C-2 情感缓存（依赖 sentiment 命中）
   │              └─→ C-6 鹰鸽落库
   ├─→ B-8 历史预加载          → market_data / news 回填（受 R2 历史长度制约）
   └─→ E-3 信号落库            → signals（依赖 B-1 + 信号生成 E-1）
          └─→ E-11 回测落库    → backtest_results
```

### 9.3 两个重要风险提醒（出自文档第 5 章）

- **⚠️ R7 / R2**：全仓无独立 XAU/USD 采集器；yfinance 分钟级历史仅 7~60 天，与「3 个月历史预加载（B-8）/ 3 个月回测（E-11）」直接冲突，必须在 Stage 0 决策（D-1 / D-2）时一并解决，否则 B-8、E-11 做不出来。
- **⚠️ R5 核心创新点未验证**：`sentiment` 落库（C-1）与情感入模（C-8）是项目最大卖点，但当前情感特征从未真实入模；文档建议将 C-8 提前为独立先导验证，决定后续投入。
