## 0.1 核心约束（不可变更，最高优先级）

本方案受用户两项**硬性约束**锁定，任何设计、开发、文档均不得违反或擅自调整：

### 约束一 · 配色方案：涨红跌绿（以现有实现为准）

- 配色逻辑固定为「**涨 / 看多 / 利多 = 红，跌 / 看空 / 利空 = 绿**」，符合国内金融用户习惯。
- **标准来源**：`frontend/dashboard.html` 定义 `--bull: oklch(54% 0.150 25)`（红）、`--bear: oklch(52% 0.120 155)`（绿）；主项目 `app/dashboard/config.py`（`#ef5350`/`#26a69a`）、`app/dashboard/utils/css.py`（`--color-up:#ef5350`/`--color-down:#26a69a`）已对齐，**禁止更改任何颜色取值**。
- 所有界面、组件、样式文件配色须与上述实现一致。V3.0 确认 `app/dashboard/` 当前已是涨红跌绿（V2.0 的 R12「需对齐」在主项目合并时已解决）。

### 约束二 · 预测窗口：固定 30 分钟

- 预测窗口**固定为未来 30 分钟**，是项目核心特色，**不得调整为日频 / T+5 等**。
- 命名约定：`HORIZON_MINUTES = 30`、`PREDICT_WINDOW = "30min"`。**注意**：该常量当前仅定义于 `gold_prediction_model/thirty_min/config.py` 与 `gold_prediction_model/config.py`，`app/` 内未使用此常量名（见 §8 存疑 C-命名）。
- 行情 / 信号 / 接口字段须体现 30 分钟粒度（如 `interval: "30min"`）。

## 第 1 章 项目背景与目标

### 1.1 项目背景

黄金兼具商品、货币、避险资产、通胀对冲等多重属性，价格受美元指数、实际利率、地缘政治、央行购金、通胀预期等复杂因素驱动。传统量化模型对美联储决议、地缘冲突等突发事件反应滞后，且难以理解「鹰派降息」「避险情绪升温」等复合金融语境。

大语言模型（LLM）的成熟为金融文本理解提供了新路径。本项目将 LLM 情感分析与传统时序预测模型融合，构建**未来 30 分钟**黄金价格（XAU/USD）方向预测系统，并以可运行 Demo 验证「LLM 情感 + 量化模型」的技术可行性与工程链路完整性。

### 1.2 项目目标（V3.0 当前阶段）

| 维度 | V3.0 目标 | 状态 |
|------|----------|------|
| 核心目标 | XAU/USD **未来 30 分钟**方向预测，产出可运行 Demo | 架构与链路已通（FastAPI + 仪表盘可启动）|
| 工程目标 | 端到端链路跑通：数据 → 情感 → 模型 → 信号 → 仪表盘 | **部分达成**：链路可跑，但数据为演示种子，**未接真实实时数据源**（见 §4 / §5）|
| 模型验证 | 完成「LLM 情感特征入模」消融，明确核心假设是否成立 | **未达成**：模型为合成数据训练，消融显示情感特征无增量（`excess_accuracy≈-0.09`）|
| 信号延迟 | 模型推理 < 3 秒；情感分析异步/缓存 | 推理满足；情感为按需调用 |
| 部署环境 | 个人笔记本本地运行（8GB+ 内存），单/双命令启动 | FastAPI（`uvicorn app.main:app`）+ Streamlit（`streamlit run app/dashboard/app.py`）|
| 配色标准 | **涨红跌绿**，以 `frontend/dashboard.html` 为准 | 已统一 |
| 准确率 | **不作 Demo 门槛**；>60% 列为独立研究指标 | 维持 |

**非目标说明**：本 Demo 非生产级系统，不追求高并发、高可用与实时交易接入；方向准确率不作为 Demo 验收门槛，效果优化作为独立研究议题后置。

### 1.3 项目定位与差异化

| 差异化维度 | 策略 | 竞品空白 |
|-----------|------|---------|
| LLM + 量化融合 | LLM 情感分数作为量化模型**特征输入**（非独立信号）| 多数产品仅侧重单一技术路线 |
| 黄金垂直聚焦 | 专注黄金单一品种，做深做透 | 竞品覆盖全市场，缺乏品种深度 |
| **30 分钟极短周期** | **固定未来 30 分钟方向预测，国内涨红跌绿配色** | 竞品多为日/周级，且多为西方涨绿跌红 |
| 可解释性优先 | 每条信号附带新闻来源 + 因子贡献度 | 黑盒评分系统缺乏透明度 |
| 渐进式演进 | FastAPI + SQLite 单体可平滑升级到 PostgreSQL/Docker 生产化 | — |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| XAU/USD | 黄金兑美元交易代码，即国际金价（Demo 以 30 分钟 K 线为预测对象）|
| **预测窗口** | **固定 30 分钟**：模型输出「未来 30 分钟黄金方向」概率（涨/跌）|
| DXY / VIX / TIPS | 美元指数 / CBOE 波动率指数 / 通胀保值债券收益率 |
| 鹰派 / 鸽派 | 倾向加息/紧缩（利空黄金）/ 倾向降息/宽松（利多黄金）|
| LLM | 大语言模型，用于新闻情感分析与事件提取（qwen-turbo）|
| 消融（Ablation）| 控制变量实验：对比「含情感特征」与「不含情感特征」的模型效果 |

### 2.2 数据层

### 2.3 模型层

- **LLM 情感（F04）**：`news_scraper_llm/analyzer.py` 三级容错（结构化 → 文本解析 → 中性降级）；需补 Few-shot、领域同义词、URL 去重缓存、每日成本熔断。
- **鹰鸽（F05）**：`app/core/hawk_dove.py` 将关键词触发 → LLM 提取 → 映射 −0.5~+0.5。

### 3.5 模型设计（固定 30 分钟窗口）

- **目标变量**：未来 30 分钟收盘价相对当前涨幅 > 0 记为「涨」，否则「跌」。
- **特征工程**：价格序列（`return`/`volatility`/`MA` 偏离等 30 分钟 rolling）、情感特征（`sentiment_mean_30`/`sentiment_max_30`）、政策特征（`hawkish_change`）、市场特征（DXY/VIX/TIPS/GPR/EPU 的 30 分钟值，`ffill` 对齐，无前视偏差）。
- **双模型集成**：LightGBM + XGBoost，加权 `p = 0.6·p_lgb + 0.4·p_xgb`。
- **防泄露**：V1.0 实现的 Purge + Walk-Forward（位于 `gold_prediction_model/`）。
- **降级链**：`WeightedPredictor` 无模型或推理异常 → `_heuristic_proba`（因子加权启发式）→ 保证信号链路可用。
- **情感特征消融**：`gold_prediction_model/` 含 ablation 实验；结论为情感特征**无显著增量**（AUC < 0.53，`excess_accuracy≈-0.09`，弱于朴素基线）。

| LLM 供应商 | qwen-turbo（DashScope）| 成本优于 GPT-4o-mini |

## 第 5 章 模型现状与已知局限

> 本章如实记录模型层的真实能力，供评审与后续研究参考。

### 5.1 运行模型的真实来源

- `app/core/predictor.py` 加载 `models/predictor.joblib`（393,417 B）。
- 该权重由 `train_synthetic_model()` 基于 **`np.random` 合成数据**训练（因子方向构造标签），**未使用任何真实市场历史**。
- 因此运行系统的「预测」本质是**合成数据上学到的因子线性关系的回放**，对真实 XAU/USD 30 分钟方向**无实证预测力**。

### 5.2 独立训练管道的验证结论

`gold_prediction_model/`（含 `thirty_min/` 子包）实现了完整方法论：

- `thirty_min/sample_data.py` 的 `generate_synthetic` 同样为合成数据；该子包训练评估准确率 ≈ 0.0。
- 消融实验 `cv_auc` 全部 < 0.54（无明显区分力）。
- `pipeline_result_nosent.json` 显示 `design_bar_interval_minutes=30` 但 `actual_bar_interval_minutes=1440`（日线数据被误标为 30 分钟）。
- `excess_accuracy = -0.09`（弱于朴素基线）。

### 5.3 结论与建议

- **R1（模型无预测力）已实证，不可再标为「已缓解」**。Demo 仍可跑通（链路完整 + 启发式降级），但信号须明确标注「演示用途，无真实预测力」。
- 后续研究路径（独立立项）：接入真实 30 分钟 XAU/USD K 线 → 重训 `gold_prediction_model/` 管道 → 复跑情感消融 → 若 AUC 增量 > 0.02 再精调。

## 附录 B · 后端设计要点（恢复自 V1.0 §19，代码已实现）

### B.1 整体架构

采集层（爬虫 + `collectors/`）→ 特征层（`feature_engineer.py`）→ 模型层（`predictor.py`）→ 信号层（`signal_generator.py`）→ API 层（`app/api/*`）→ 展示层（`app/dashboard/`）。

### B.2 采集调度策略

`app/core/scheduler.py`（APScheduler）：`collect_interval_seconds=60`（因子采集）、`signal_interval_seconds=300`（信号生成）。`DEMO_MODE=True`（默认）时不启动常驻调度；`DEMO_MODE=False` 时进入 LIVE 常驻模式。

### B.3 DEMO-LIVE 模式切换

通过 `app/config.py` 的 `DEMO_MODE` 切换：
- **DEMO**：使用种子/缓存数据，调度关闭，便于本地演示。
- **LIVE**：启用 APScheduler 常驻采集 + 信号，接真实数据源。

### B.4 爬虫适配与集成

`app/core/factor_collectors.py` + `app/core/collectors/`（base/adapters）统一封装各爬虫输出为标准化因子；`news_scraper_llm/` 独立运行写入新闻 + 情感（待接入 `sentiment` 表）。
