## 第 1 章 项目概述

### 1.1 项目背景

黄金兼具商品、货币、避险资产、通胀对冲等多重属性，价格受美元指数、实际利率、地缘政治、央行购金、通胀预期等复杂因素驱动。传统量化模型依赖历史价格和技术指标，对美联储决议、地缘冲突等突发事件反应滞后，且难以理解"鹰派降息"、"避险情绪升温"等复合金融语境。

大语言模型（LLM）的成熟为金融文本理解提供了新路径。LLM 能实时解析新闻、官员讲话、地缘事件，提取对黄金的利多/利空程度。本项目将 LLM 情感分析与传统时序预测模型深度融合，构建 30 分钟级别的黄金价格方向预测系统。

### 1.2 项目目标（Demo 阶段）

| 维度 | 目标 |
|------|------|
| 核心目标 | 30 分钟级别黄金价格（XAU/USD）方向预测，产出可运行 Demo |
| 方向准确率 | > 60%（3 个月回测验证） |
| 信号延迟 | < 3 秒（从新闻发布到信号输出） |
| 部署环境 | 个人笔记本本地运行（8GB+ 内存） |
| 交付周期 | 14 天 |

**非目标说明**：本 Demo 非生产级系统，不追求高并发、高可用性（99.99%+）和实时交易接入。核心价值在于验证"LLM 情感分析 + 量化模型"的技术可行性和预测效果。

### 1.3 项目定位与差异化

| 差异化维度 | 策略 | 竞品空白 |
|-----------|------|---------|
| 极短周期预测 | 专注 30 分钟级别方向预测 | Kavout 以日线为主，AlphaSense 无预测功能 |
| LLM + 量化融合 | LLM 情感分数作为量化模型特征输入 | 多数产品仅侧重单一技术路线 |
| 黄金垂直聚焦 | 专注黄金单一品种，做深做透 | 竞品覆盖全市场，缺乏品种深度 |
| 可解释性优先 | 每条信号附带新闻来源和因子贡献度 | 黑盒评分系统缺乏透明度 |

### 1.4 Demo 范围与约束

| 维度 | 说明 |

| 功能范围 | P0 全部 + P1 部分（鹰鸽指数、回测、准确率统计） |

| 术语 | 定义 |
|------|------|
| XAU/USD | 黄金兑美元的交易代码，即国际金价 |
| DXY | 美元指数（US Dollar Index） |

## 第 2 章 用户与场景分析

### 2.1 用户角色定义

| 角色 | 描述 | Demo 阶段定位 |
|------|------|-------------|
| 交易员 | 黄金市场短线交易者，需要实时信号快速决策 | 主要演示对象 |
| 研究员 | 量化策略研究员，需要回测信号评估准确率 | 次要演示对象 |
| 系统管理员 | 系统运维人员，监控系统状态和数据质量 | 开发者本人兼任 |

### 2.2 核心使用场景

**场景一：实时信号监控**

交易员打开 Streamlit 仪表盘，查看当前黄金价格走势、最新交易信号（看涨/看跌/观望 + 强度 + 建议仓位）、最新新闻及情感标签、各因子实时数值。每 5 分钟自动刷新信号。

**场景二：模拟交易回测**

研究员在仪表盘选择回测时间范围（如近 3 个月），点击"运行回测"，系统使用 Backtrader 模拟历史交易，输出收益率、夏普比率、最大回撤、胜率、盈亏比等指标，并展示收益曲线。

**场景三：事件驱动分析**

重大新闻发布（如美联储主席讲话），系统自动采集 → LLM 情感分析 → 特征更新 → 模型推理 → 信号生成，全链路 < 3 秒完成。交易员在仪表盘看到信号变化和新闻归因。

### 2.3 用户痛点与需求映射

| 角色 | 痛点 | Demo 解决方案 |
|------|------|-------------|
| 交易员 | 决策滞后、信息过载 | Streamlit 仪表盘 + 每 5 分钟信号 + 多空评分 |
| 研究员 | 回测工具缺失、归因困难 | Backtrader 集成 + 信号归因与引用溯源 |
| 管理员 | 监控分散 | Streamlit 状态面板（数据采集状态、API 调用量、模型准确率） |

### 3.2 数据层功能设计

#### F01 新闻数据采集

- **数据源**：NewsAPI 免费层（100 请求/天），GNews 备选
- **采集频率**：每分钟轮询
- **采集内容**：黄金相关新闻（标题、正文摘要、来源、发布时间、URL）
- **关键词过滤**：gold、XAU、Fed、interest rate、inflation、geopolitical 等
- **数据清洗**：去重（URL + 标题相似度）、时间戳标准化
- **存储**：PostgreSQL news 表

#### F02 市场数据采集

- **数据源**：yfinance（免费、稳定）
- **采集指标**：

| 指标 | yfinance 代码 | 用途 |
|------|--------------|------|
| XAU/USD | GC=F | 黄金期货价格 |
| 美元指数 | DX-Y.NYB | DXY |
| VIX | ^VIX | 恐慌指数 |
| 美国 10Y TIPS ^IRX | 实际利率代理 |

- **采集频率**：分钟级实时采集
- **存储**：PostgreSQL market_data 表

### 3.3 模型层功能设计

#### F04 新闻情感分析

- **技术方案**：LangChain ChatOpenAI + PromptTemplate
- **LLM 模型**：GPT-4o-mini（性价比最高）
- **输入**：新闻标题 + 正文摘要
- **输出**：

| 字段 | 类型 | 范围 | 说明 |
|------|------|------|------|
| sentiment_score | float | -1 ~ +1 | 情感分数（-1 强烈利空，+1 强烈利多） |
| topic | string | — | 主题标签（Fed、Geopolitical、Inflation 等） |
| confidence | float | 0 ~ 1 | 置信度 |
| key_sentence | string | — | 关键句（用于引用溯源） |

- **Prompt 策略**：System Prompt + Few-shot 示例（3-5 条）+ 黄金领域同义词库

#### F05 鹰鸽指数计算

- **触发条件**：新闻中检测到美联储官员讲话
- **处理逻辑**：LLM 从讲话文本中提取鹰派/鸽派程度
- **映射规则**：鹰派 → -0.5（利空黄金），鸽派 → +0.5（利多黄金）
- **输出**：鹰鸽分数 + 超预期程度

#### F07 时序预测模型

- **基线模型**：LightGBM
- **对比模型**：XGBoost
- **预测目标**：未来 30 分钟 XAU/USD 上涨概率（0 ~ 1）
- **输入特征**：

| 特征类别 | 具体特征 |
|---------|---------|
| 价格序列 | 30 分钟收益率、波动率、买卖价差 |
| 情感特征 | 滚动窗口情感均值/极值 |
| 政策特征 | 鹰鸽指数变化量 |
| 市场特征 | DXY 收益率、TIPS 变化、VIX 水平 |

- **输出**：上涨概率 + 预估收益率 + 置信度

### 3.4 应用层功能设计

#### F08 信号生成器

- **触发方式**：APScheduler 每 5 分钟触发
- **生成流程**：

```
数据采集 → 特征组装 → 模型推理 → 多因子聚合 → 信号输出
    ↓           ↓          ↓          ↓           ↓
 yfinance    Pandas    LightGBM   加权融合    方向+强度
 NewsAPI    特征工程   XGBoost    置信度      +仓位建议
```

- **信号输出格式**：

| 字段 | 说明 |
|------|------|
| direction | 看涨 / 看跌 / 观望 |
| probability | 上涨概率（0~1） |
| strength | 信号强度（0-100） |
| position | 轻仓 / 中仓 / 重仓 |
| factors | 因子贡献度归因 |
| news_refs | 新闻来源引用 |

- **防抖策略**：连续 3 次信号方向反转时输出"观望"
- **降级策略**：LLM 不可用时仅用量化模型，置信度 < 0.55 输出"观望"

#### F09 可视化仪表盘

Streamlit 单页应用，包含：
1. 实时黄金价格走势图（Plotly 折线图，1 分钟刷新）
2. 当前信号卡片（方向、概率、强度、仓位建议、多空评分）
3. 最新新闻列表 + 情感标签（绿=利多、红=利空、灰=中性）
4. 因子实时数值面板（DXY、TIPS、VIX、情感分数、鹰鸽指数）
5. 历史准确率统计图表（7 天/30 天滚动窗口）
6. 回测收益曲线

#### F10 模拟交易回测

- **框架**：Backtrader
- **回测范围**：3 个月历史数据
- **模拟参数**：点差 0.3 美元、手续费 0.01%
- **输出指标**：收益率、夏普比率、最大回撤、胜率、盈亏比

#### F11 历史准确率统计

- 滚动窗口统计（7 天/30 天）
- 按信号方向分类统计准确率
- 与买入持有基准对比

### 3.5 功能优先级与技术依赖

```
F01 新闻采集 ──→ F04 情感分析 ──→ F07 时序预测 ──→ F08 信号生成 ──→ F09 仪表盘
F02 市场采集 ──→ 特征工程 ─────→ F07 时序预测 ──→ F08 信号生成 ──→ F09 仪表盘
                                    F05 鹰鸽指数 ──→ 特征工程
F08 信号生成 ──────────────────→ F10 回测 ──→ F11 准确率统计
```

## 第 4 章 用户故事与验收标准

### 4.1 P0 优先级用户故事

**US-001 新闻数据采集**
> 作为系统管理员，我希望系统自动实时抓取与黄金相关的新闻、公告和官员讲话，以便为预测模型提供实时事件输入。

- 验收标准：每分钟采集一次，数据写入 PostgreSQL news 表
- 异常场景：API 返回 429 限流时指数退避重试；网络超时 30 秒记录日志并跳过

**US-002 市场数据采集**
> 作为系统管理员，我希望系统实时采集黄金价格、美元指数、利率等核心市场数据，以便构建预测特征。

- 验收标准：yfinance 分钟级数据写入 market_data 表
- 异常场景：市场闭市期间无数据时标记为"非交易时段"

**US-003 新闻情感分析**
> 作为研究员，我希望系统使用 LLM 对新闻进行情感分析，输出黄金利多/利空分数（-1 ~ +1），以便量化新闻对价格的影响。

- 验收标准：每条新闻调用 LLM 输出 sentiment_score、topic、confidence
- 异常场景：LLM API 超时时降级为规则引擎（关键词匹配）

**US-004 时序预测模型**
> 作为研究员，我希望系统基于多因子输入输出未来 30 分钟上涨概率，以便生成交易信号。

- 验收标准：LightGBM + XGBoost 双模型输出概率，取加权平均
- 异常场景：关键特征缺失时用前值填充，并在信号中标记

**US-005 信号生成**
> 作为交易员，我希望系统每 5 分钟生成一次交易信号（看涨/看跌/观望 + 强度 + 建议仓位），以便快速决策。

- 验收标准：APScheduler 每 5 分钟触发，信号写入 signals 表并推送到仪表盘
- 异常场景：模型推理超时 3 秒时输出"观望"并记录告警

**US-006 仪表盘**
> 作为交易员，我希望通过 Streamlit 仪表盘实时查看黄金价格走势、当前信号、最新新闻及各因子数值，以便全面掌握市场状态。

- 验收标准：页面加载 < 3 秒，数据刷新 < 5 秒
- 异常场景：数据库连接失败时显示"连接中断，重试中"

### 4.2 P1 优先级用户故事（Demo 选中）

**US-007 鹰鸽指数**
> 作为研究员，我希望系统从央行官员讲话中提取鹰派/鸽派程度并映射为黄金影响因子（-0.5 ~ +0.5），以便捕捉货币政策预期变化。

- 验收标准：检测到美联储官员讲话时自动触发 LLM 提取
- 异常场景：讲话同时包含鹰派和鸽派表述时取加权平均

**US-008 回测验证**
> 作为研究员，我希望使用 Backtrader 对历史信号进行回测，模拟交易费用和滑点，以便验证策略有效性。

- 验收标准：3 个月历史数据回测完成，输出收益率/夏普/最大回撤
- 异常场景：历史数据缺失时提示"数据不完整，请扩大采集范围"

**US-009 准确率统计**
> 作为研究员，我希望查看信号的历史准确率、盈亏比统计，以便评估模型表现。

- 验收标准：支持 7 天/30 天滚动窗口统计
- 异常场景：无交易信号期间分母为零时显示"数据不足"

### 9.2 LLM 情感分析模型

#### Prompt 工程

**System Prompt**：

```
你是黄金市场新闻情感分析专家。分析以下新闻对黄金价格（XAU/USD）的影响。

输出 JSON 格式：
{
  "sentiment_score": float,  // -1(强烈利空) ~ +1(强烈利多)
  "topic": string,           // Fed/Inflation/Geopolitical/Dollar/Other
  "confidence": float,       // 0~1
  "key_sentence": string     // 影响判断的关键句
}

判断规则：
- 美联储加息/鹰派 → 利空黄金（负分）
- 美联储降息/鸽派 → 利多黄金（正分）
- 地缘冲突升级 → 避险需求上升 → 利多黄金
- 美元升值 → 利空黄金
- 通胀超预期 → 黄金保值需求上升 → 利多黄金
```

**Few-shot 示例**：

| 新闻标题 | 期望输出 |
|---------|---------|
| "Fed holds rates steady, signals no cuts until Q3" | score: -0.6, topic: Fed |
| "Middle East tensions escalate, oil surges" | score: +0.7, topic: Geopolitical |
| "US CPI comes in below expectations" | score: +0.3, topic: Inflation |

#### 黄金领域同义词库

| 标准词 | 同义词 |
|--------|--------|
| 加息 | rate hike, tighten, hawkish, contractionary |
| 降息 | rate cut, ease, dovish, expansionary |
| 量化宽松 | QE, quantitative easing, money printing |
| 避险 | safe haven, risk-off, flight to safety |
| 通胀 | inflation, CPI, PCE, price pressure |

#### 输出解析

使用 LangChain `StrOutputParser` + Pydantic 模型结构化解析，确保输出格式一致。LLM 返回非标准格式时降级为规则引擎（关键词匹配）。

### 9.3 鹰鸽指数模型

**触发条件**：新闻标题或正文中检测到美联储官员姓名或"Fed"、"FOMC"、"Federal Reserve"关键词。

**处理流程**：

1. LLM 提取讲话中的鹰派/鸽派表述

### 10.3 Backtrader 回测

```python
import backtrader as bt

class GoldSignalStrategy(bt.Strategy):
    """基于信号文件的回测策略"""

    params = (
        ('spread', 0.3),       # 点差 0.3 美元
        ('commission', 0.0001), # 手续费 0.01%
    )

    def next(self):
        signal = self.get_signal(self.data.datetime.date(0))

        if signal == 'bullish' and not self.position:
            self.buy(size=self.calculate_position())
        elif signal == 'bearish' and self.position:
            self.close()

    def calculate_position(self):
        """基于信号强度的仓位计算"""
        strength = self.get_signal_strength()
        if strength > 70:
            return self.broker.getcash() * 0.08 / self.data.close[0]  # 重仓 8%
        elif strength > 50:
            return self.broker.getcash() * 0.05 / self.data.close[0]  # 中仓 5%
        else:
            return self.broker.getcash() * 0.03 / self.data.close[0]  # 轻仓 3%
```

## 第 12 章 非功能需求保障

### 12.1 性能保障

| 指标 | 目标 | 保障措施 |
|------|------|---------|
| 信号生成延迟 | < 3 秒 | LightGBM 推理毫秒级；LLM 调用 < 500ms（GPT-4o-mini） |
| 仪表盘加载 | < 3 秒 | Streamlit `@st.cache_data` 缓存机制 |
| 数据采集 | < 30 秒 | httpx 异步请求，并行采集 |
| 模型训练 | < 5 分钟 | 3 个月数据 + LightGBM，笔记本 CPU 足够 |

### 12.2 准确性保障

- **双模型对比**：LightGBM + XGBoost，若两模型方向不一致则降低置信度
- **Few-shot 示例**：3-5 条标准示例提升 LLM 情感分析一致性
- **人工抽检**：每周随机抽取 50 条新闻，人工标注与 LLM 输出对比，目标一致率 > 85%
- **模型漂移检测**：滚动 30 天准确率低于 55% 时触发告警

### 12.3 稳定性保障

| 场景 | 保障措施 |
|------|---------|
| 数据采集失败 | httpx + 指数退避重试（3 次） |
| LLM API 超时 | 降级为规则引擎（关键词匹配），信号标记为"低置信度" |
| 数据库连接失败 | SQLAlchemy 连接池自动重连 |
| 笔记本休眠 | APScheduler `misfire_grace_time` 配置，唤醒后自动补执行 |

### 12.4 成本控制

| 成本项 | 控制措施 |
|--------|---------|
| OpenAI API | 每日调用上限 $5；相同新闻缓存情感结果（URL 去重） |
| NewsAPI | 免费层 100 请求/天，每分钟轮询但合并请求 |
| 本地存储 | 数据量 < 1GB（3 个月分钟级数据约 30 万行） |
| 计算资源 | LightGBM/XGBoost 纯 CPU，无需 GPU |

## 第 17 章 项目创新点

### 17.1 技术创新

1. **LLM 情感分析作为量化模型特征**：将 LLM 输出的情感分数作为 LightGBM/XGBoost 的输入特征，而非独立信号，实现"语义理解 → 量化预测"的深度融合
2. **双模型对比验证**：LightGBM + XGBoost 双模型 A/B 对比，提高信号稳健性
3. **极短时预测（30 分钟）**：填补市场空白，竞品多以日线/小时线为主

### 17.2 产品创新

1. **黄金多空评分系统**：将多因子融合为 0-100 单一评分，降低交易员认知负担
2. **信号归因与引用溯源**：每条信号附带新闻来源 URL 和关键句，增强可信度
3. **黄金领域同义词库**：构建 QE=量化宽松=印钞等金融同义词库，提升 LLM 金融语义理解

### 17.3 体验创新

1. **可解释性优先**：信号附带因子贡献度分析，用户能理解"为什么"输出该信号
2. **Streamlit 一站式仪表盘**：数据 + 信号 + 回测 + 统计 + 归因一体化展示
