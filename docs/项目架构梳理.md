# 「点时成金」项目架构梳理

> 黄金价格 30 分钟方向预测系统 · 架构现状快照
> 生成日期：2026-08-06
> 分析范围：工作区根目录全部源码（排除 `.venv` / `__pycache__`）

---

## 1. 一句话定位

这不是常规 Web 业务系统，而是一条 **「多源数据采集 → 因子/特征工程 → 方向信号 → 可视化终端」的量化预测流水线**。技术形态是纯 Python 后端 + 数据科学栈，前端仅为展示外壳（Streamlit + 一个静态 HTML 原型）。

## 4. 关键架构模式与设计决策

### 4.1 爬虫统一模板约定

7 个文件型爬虫遵循同一套**扁平式六件套**：

```
config.py    目标 URL、请求头、重试参数、输出路径常量
scraper.py   网络抓取（含指数退避重试）
parser.py    HTML/Excel 解析（仅在需要时存在）
storage.py   双写落盘
utils.py     日志初始化、限速
main.py      入口编排
```

统一落盘规则：`OUTPUT_DIR = <根>/data`，`LOG_DIR = <根>/logs`，产出恒为 **`X_latest.json`（当前快照）+ `X_history.jsonl`（追加历史）** 这一对。这是一个很清晰的约定优于配置的设计。

**偏离者**：`xauusd_30m_scraper`（client/parser/aggregator/scheduler 另一套）、`news_scraper_llm`（scrapers 子包 + analyzer/llm_client/db，唯一写 SQLite）。

### 4.2 适配器模式解决模块名冲突

各爬虫用「裸名模块」（`config` / `scraper` / `utils`）组织，彼此同名会互相污染 `sys.modules`。`app/core/factor_collectors.py` 用 `_load_scraper_module()` 在**隔离的 sys.path 下逐个动态加载**，加载前主动清除同名残留模块。这是本项目最巧妙的一个工程决策，代价是牺牲了静态可分析性。

### 4.3 方言自适应的数据访问

`database.py` 按 `DATABASE_URL` 前缀自动切换策略：
- SQLite：不传 pool 参数、`check_same_thread=False`、连接事件挂 `WAL` + `busy_timeout=5000` + `foreign_keys=ON`
- PostgreSQL：真实连接池 + `pool_pre_ping`

`tables.py` 做了完整的 PG→SQLite 可移植适配：`JSONB→JSON`、`BigInteger→Integer`、`text("col DESC")→desc(col)`、`Uuid` 自动降级 CHAR(32)。**切回 PostgreSQL 只需改一行 DATABASE_URL**——移植性设计做得很到位。

### 4.4 幂等写入

所有落库路径统一走 upsert，冲突目标为真实唯一约束：
- `market_data`：`uq_market_data_ts_sym (timestamp, symbol)`
- `news`：`url` 唯一（url 为空时退化为 `source+title`）
- `sentiment`：`uq_sentiment_news_model_mode (news_id, model_version, sentiment_mode)`
- `scraped_gold_prices`：`(source, symbol, quote_date)`

### 4.5 优雅降级（三处）

1. **仪表盘降级**：`DEMO_MODE=True` 时 `api/client.py` 读本地 `demo_data/*.json`，后端不可用也能独立演示
2. **LLM 降级**：结构化输出失败 → 正则手动解析 → 指数退避重试 → 最终降级为「中性 + 低置信」，保证流水线不中断
3. **爬虫降级**：`app/pipeline/scraper.py` 无网络时回退内置样本 HTML；模型 30 分钟 bar 不足 200 根时回退合成数据

### 4.6 防数据泄漏的时序验证

模型侧做得相当规范：时序 70/15/15 不打乱 + **Purge/Embargo**（López de Prado，边界剔除 HORIZON 根 bar）+ **Purged Walk-Forward CV**（5 折扩张窗口，超参仅在开发集内选）+ 过拟合 gap 检测 + majority/always_up 基线对照。

### 4.7 LLM 调用成本控制

分析前先 `db.select_unanalyzed()` 按 `(url, model_version, mode)` 过滤，已分析的直接跳过 LLM 调用；并发用 `asyncio.Semaphore(3)` 限流。

## 5. 依赖关系

```
app/dashboard ──► app/dashboard/api/client ──► demo_data/*.json   （当前实际路径）
                                          └──► [FastAPI /api/v1/*]（配置了但未实现）

app/core ──► app/models（ORM/引擎）
        └──► 各 scraper 包（动态隔离加载，非静态 import）

app/pipeline ──► app/models.database（共用引擎）
            └──► app/core.data_collector._dialect_insert（复用 upsert）

gold_prediction_model ──► data/*.jsonl + data/news_scraper_output/*.json
                     ✗   与 app/ 无任何 import 关系
```

依赖方向整体是**单向向下**的，没有循环依赖，分层边界清楚。唯一的例外是 `app/pipeline` 反向复用了 `app/core` 的私有函数 `_dialect_insert`。

## 7. 架构断点与风险（重点）

### 断点 ① API 层在工作区缺失，版本已分叉

`forecasts-for-gold-prices-main/` **不是简单副本**，而是团队主干版本，它独有：
- `app/api/` —— 8 组 FastAPI 路由（`signals` / `market` / `factors` / `news` / `backtest` / `stats` / `hawk-dove` / `system`），统一 `ApiResponse` 响应模型，`deps.py` 依赖注入
- `app/main.py` —— FastAPI 实例与路由挂载
- `Dockerfile` + `docker-compose.yml`（api 服务暴露 8000，dashboard/postgres 服务已注释预留）
- `pytest.ini`、`app/core/collectors/`（base + adapters）、`app/core/feature_engineer.py`

而工作区版本独有：`app/core/bootstrap_data.py`、`data_quality.py`、`factor_collectors.py`、`hawk_dove.py`、`app/pipeline/`、`app/config.py`。

**两个版本各有对方没有的模块，需要一次合并**。git 只有一个 initial commit，大量新文件仍处于 untracked 状态。

### 断点 ② 模型链与业务链完全解耦

`grep` 确认 `app/` 目录 **0 处** import `gold_prediction_model`。`signal_generator.py` 用的是 6 因子人工加权规则，其 docstring 明确写道：「本工程当前未含该模型，故采用透明规则打分……后续接入模型时只需替换 `_build_factors`」。模型侧 `Predictor.predict_direction()` 接口是齐备的，属于「接口就绪、未接线」。

### 断点 ③ 仪表盘仍在演示模式

`DashboardConfig.DEMO_MODE = True`，`api/client.py` 全部 12 个方法都只是 `_load_demo()` 读本地 JSON，`API_BASE_URL` 形同虚设。仪表盘与 SQLite 之间没有任何真实连接。

### 断点 ④ 30 分钟历史行情未落盘

`data/xauusd_30m_bars.jsonl` 不存在（只有 `_latest_bar.json`），真实 bar 数 < 200，`thirty_min` 模型自动回退合成数据。其报告中 acc 0.757 / AUC 0.826 标注了 `"source": "synthetic"`，**不可作为效果依据**。

### 风险 ⑤ 模型当前无预测力

`analysis_summary.json` 显示 T+30 清洁测试 **accuracy 0.487 / AUC 0.494**，而 naive 基线 0.616，超额 **-0.13**。消融实验显示加入 GPR/EPU 为负增益。`metrics.json` 中 ensemble test acc 0.639 是未做清洁选择的乐观值（AUC 仅 0.506）。

### 风险 ⑥ 其他

- `fred_scraper` 7 个 py 全为空文件，但 `data/` 里仍有其历史产出，属于「有数据无代码」
- `gold_scraper_framework` 仅剩 Python 3.6 字节码，与项目其余 3.13 代码不同代，应清理
- 测试覆盖极薄：仅 1 个测试文件，核心的 `signal_generator` / `backtest` / 模型全无测试
- 7 个文件型爬虫全部只写文件不写库，`app/core/factor_collectors.py` 虽实现了写库适配，但相关表仍为 0 行——说明该适配层尚未被实际调度执行
