1. **架构事实化**：V2.0 显式「不引入 FastAPI/PostgreSQL/Docker/APScheduler」，但后端合并已落地 FastAPI + SQLite + SQLAlchemy + APScheduler + Streamlit（与 V1.0 一致）。V3.0 正式采纳此架构，删除「不引入」声明。
2. **恢复 V1.0 独有文档**：API 接口规格（§附录 A，12 端点 + 响应信封 + 错误码）与后端设计（§附录 B，采集调度 / DEMO-LIVE 切换）在 V2.0 中被精简，代码已按此实现，V3.0 恢复为权威契约。
3. **模型现状如实记录**：V2.0 将 R1（模型无预测力）标「已缓解」；实测证实运行模型为 `np.random` 合成数据训练，`excess_accuracy≈-0.09`，无真实预测力。V3.0 单列 §5 记录，并标注信号「演示用途」。
4. **存储由本地 JSON 改为 SQLite**：9 表已落地，但当前均为 `seed.py`/`bootstrap_data.py` 演示种子；真实爬虫输出未接入（`scraped_gold_prices`/`economic_calendar`/`sentiment` 表 0 行）。
5. **配色 R12 状态修正**：主项目 `app/dashboard/` 已统一涨红跌绿（#ef5350/#26a69a），无需再对齐。
6. **`imports.py` 桥接层未创建**：V2.0 强制要求的 `app/core/imports.py` 实际不存在，导入冲突通过 `app/core/collectors/` + `factor_collectors.py` 的 sys.path 隔离解决（目标达成，机制不同）。
7. **Docker 资产补回**：建议 3 迁移的 `Dockerfile`/`docker-compose.yml` 与 V1.0 生产化路径一致。
