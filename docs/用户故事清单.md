# 「点时成金」用户故事清单

> 基于《点时成金：黄金价格 30 分钟方向预测系统》需求规格说明书拆解
> 文档版本：v1.0 | 创建日期：2026-06-22

---

## 原始需求核心目标总结

**核心业务目标**：开发一套 AI 驱动的黄金价格（XAU/USD）30 分钟方向预测系统，通过 LLM 实时解析新闻情感 + 多因子时序模型，输出交易信号，实现方向准确率 >60%、盈亏比 >1.5、信号延迟 <3 秒。

**关键用户角色**：交易员（实时决策）、研究员（回测分析）、系统管理员（运维监控）

---

## 【P0 优先级】核心功能 — 没有这些系统无法运行

### 1. 数据采集层

- **作为系统管理员，我希望系统自动实时抓取与黄金相关的新闻、公告和官员讲话，以便为预测模型提供实时事件输入**
  - 异常场景：新闻 API 服务中断或返回 429 限流；网络超时超过 30 秒
  - 边界条件：API 返回空数据或格式异常；同一新闻被多个源重复抓取；新闻发布时间戳与系统时间偏差超过 5 分钟

- **作为系统管理员，我希望系统实时采集黄金价格、美元指数、利率等核心市场数据，以便构建预测特征**
  - 异常场景：数据源 API 故障或维护；市场闭市期间无数据更新
  - 边界条件：价格数据出现跳空（如周末）；单条数据缺失超过 3 分钟；价格出现负值或极端异常值（如闪崩/闪涨超过 5%）

### 2. 模型层

- **作为研究员，我希望系统使用 LLM 对新闻进行情感分析，输出黄金利多/利空分数（-1 ~ +1），以便量化新闻对价格的影响**
  - 异常场景：LLM API 超时或限流；LLM 返回非标准格式（无法解析为分数）
  - 边界条件：新闻文本为空或仅包含标题；新闻语言为非英语（如中文、阿拉伯语）；单条新闻字符数超过模型上下文限制；情感置信度低于 0.6 时的处理策略

- **作为研究员，我希望系统基于多因子输入（价格序列、情感特征、市场特征等）输出未来 30 分钟上涨概率，以便生成交易信号**
  - 异常场景：某个关键特征缺失（如 DXY 数据延迟）；模型推理超时；模型输出概率超出 [0,1] 范围
  - 边界条件：训练数据与当前市场 regime 差异过大（如黑天鹅事件）；特征值超出训练分布 3 个标准差；滚动窗口内数据点不足（如刚启动时）

### 3. 应用层

- **作为交易员，我希望系统每 5 分钟生成一次交易信号（看涨/看跌/观望 + 强度 + 建议仓位），以便快速决策**
  - 异常场景：信号生成器依赖的某个模块故障（如 LLM 服务宕机）；信号生成耗时超过 3 秒
  - 边界条件：模型置信度低于阈值（如 <0.55）时应输出"观望"；连续多次信号方向反转的防抖处理；市场高波动期间（VIX >40）信号降级策略

- **作为交易员，我希望通过 Streamlit 仪表盘实时查看黄金价格走势、当前信号、最新新闻及各因子数值，以便全面掌握市场状态**
  - 异常场景：WebSocket 连接断开；仪表盘后端服务崩溃；数据库连接池耗尽
  - 边界条件：同时在线用户超过 10 人时的性能表现；数据刷新频率与前端渲染的平衡；移动端浏览器兼容性

## 【P1 优先级】重要功能 — 显著提升产品价值

### 4. 宏观与政策因子

- **作为研究员，我希望系统从央行官员讲话中提取鹰派/鸽派程度并映射为黄金影响因子（-0.5 ~ +0.5），以便捕捉货币政策预期变化**
  - 异常场景：讲话文本非结构化（如 PDF/图片格式）；讲话内容同时包含鹰派和鸽派表述
  - 边界条件：同一官员短期内多次讲话的去重与加权；讲话与市场已有预期的对比（超预期程度）

- **作为研究员，我希望系统从新闻中提取地缘政治风险强度（0 ~ 1），以便量化避险需求对黄金的支撑**
  - 异常场景：新闻中地缘关键词误触发（如体育赛事中的"冲突"）；多个地缘事件同时发生时的叠加计算
  - 边界条件：滑动窗口平滑的窗口长度选择；地缘风险分数持续高位（>0.8）超过 24 小时的衰减策略

### 5. 宏观经济数据

- **作为系统管理员，我希望系统自动采集非农、CPI、GDP 等宏观经济数据，以便在数据发布时捕捉超预期冲击**
  - 异常场景：经济数据发布时间延迟或提前；实际值与预期值同时缺失
  - 边界条件：数据发布时的瞬时流量峰值处理；历史数据修订时的回溯更新策略

### 6. 回测与验证

- **作为研究员，我希望使用 Backtrader 对历史信号进行回测，模拟交易费用和滑点，以便验证策略有效性**
  - 异常场景：历史数据缺失导致回测中断；回测参数配置错误（如起始日期晚于结束日期）
  - 边界条件：回测时间跨度至少 3 年；不同市场环境（牛市/熊市/震荡）下的分段回测；过拟合检测（训练集与测试集表现差异 >15%）

- **作为研究员，我希望查看信号的历史准确率、盈亏比、夏普比率和最大回撤统计，以便评估模型表现**
  - 异常场景：统计数据计算时分母为零（如无交易信号期间）
  - 边界条件：胜率与盈亏比的权衡展示；按时间段（近 7 天/30 天/90 天）的滚动统计；与基准（如买入持有）的对比

### 7. 系统可靠性

- **作为系统管理员，我希望系统在数据采集失败时自动重试并告警，以便及时发现和修复数据链路问题**
  - 异常场景：重试 3 次后仍然失败；告警通道（邮件/短信/Webhook）同时故障
  - 边界条件：重试间隔的指数退避策略；非交易时段的告警降噪处理

## 【P2 优先级】锦上添花 — 可后续迭代

### 8. 佐证与长期因子

- **作为研究员，我希望系统采集 COMEX 黄金非商业净持仓和 ETF 资金流向数据，以便从投机情绪角度辅助判断**
  - 异常场景：CFTC COT 报告延迟发布（每周五但常有延迟）；ETF 数据源不一致
  - 边界条件：周度低频数据与分钟级高频信号的融合策略；持仓极端值（历史最高/最低）时的反转预警

- **作为研究员，我希望系统展示央行购金、矿业成本等长期结构性因素，以便理解黄金的长期支撑逻辑**
  - 异常场景：季度/年度数据更新频率过低导致展示陈旧
  - 边界条件：长期因子与短期预测信号的区分展示；避免低频数据对高频信号的干扰

### 9. 外部接口与扩展

- **作为交易员，我希望通过 RESTful API 或 WebSocket 获取实时信号，以便集成到自有交易系统**
  - 异常场景：API 认证失败；WebSocket 客户端异常断开
  - 边界条件：API 速率限制（如 100 次/分钟）；数据格式版本兼容性

- **作为研究员，我希望导出历史数据和交易明细为 CSV/Excel，以便进行离线分析**
  - 异常场景：导出数据量过大导致内存溢出；文件编码问题
  - 边界条件：单次导出时间范围限制（如最多 1 年）；大文件分片下载

### 10. 知识图谱与归因

- **作为研究员，我希望系统展示多因子归因分析，说明当前信号的主要驱动因素，以便理解模型决策逻辑**
  - 异常场景：归因算法（如 SHAP）计算超时；多因子共线性导致归因不稳定
  - 边界条件：归因结果的可解释性阈值；用户自定义关注的因子优先级

## 补充建议

### 一、未覆盖的重要场景

| 场景 | 说明 | 建议处理方式 |
|------|------|-------------|
| **市场极端波动** | 黄金单日波动超过 3% 的异常行情 | 增加"市场状态"分类（正常/高波动/极端），高波动期自动降低仓位建议或暂停信号 |
| **重大节假日** | 圣诞、元旦等流动性极低时段 | 识别低流动性时段，信号降级并提示"流动性风险" |
| **模型漂移检测** | 模型在实盘中的性能逐渐下降 | 实时监控准确率滚动窗口，低于 55% 触发模型重训练或告警 |
| **多时间框架冲突** | 30 分钟看涨但日线看跌 | 增加更高时间框架的趋势过滤，避免逆势交易 |
| **新闻真伪验证** | 假新闻或洋葱新闻被误采信 | 引入新闻来源可信度评分，低可信度来源降权或人工审核 |

### 二、潜在技术风险

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| **LLM 幻觉导致情感误判** | 高 | LLM 可能误解"加息"对黄金的短期/长期影响，建议增加 few-shot 示例和人工抽检机制 |
| **特征泄露（Look-ahead Bias）** | 高 | 回测时务必确保特征计算不使用未来数据，特别是"超预期"特征 |
| **数据获取的法律合规** | 中 | 爬虫抓取需遵守 robots.txt 和网站 ToS，建议优先使用官方 API |
| **模型过拟合高频噪声** | 中 | 30 分钟级别的随机性较高，建议增加正则化和 Walk-Forward 验证 |
| **实时推理成本失控** | 中 | LLM 调用费用可能随新闻量激增，建议设置每日调用上限和缓存机制 |

### 三、推荐的验证方法

1. **A/B 测试框架**：同时运行 LightGBM 基线模型和 LSTM 进阶模型，对比实盘表现
2. **模拟交易阶段**：正式上线前至少运行 2 周模拟交易，验证端到端延迟和稳定性
3. **人工抽检机制**：每周随机抽取 50 条新闻，人工标注情感并与 LLM 输出对比，目标一致率 >85%
4. **压力测试**：模拟 10 个并发用户 + 突发新闻高峰（如美联储决议），验证系统响应
5. **灾难恢复演练**：模拟数据库故障、LLM API 宕机，验证系统降级 gracefully 的能力
