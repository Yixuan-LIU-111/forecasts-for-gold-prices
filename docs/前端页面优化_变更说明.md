## 3. 接口变更点

### 新增接口
- **`GET /api/v1/system/data-sources`**（S5）
  - 响应 `data: [{ indicator_code, indicator_name, source_name, source_url, update_frequency, realtime, description }]`
  - 数据来自 `data_sources` 表（8 条真实来源：VIX/CBOE、DXY、TIPS、GPR、EPU、FRED、新浪财经、鹰鸽指数等）
- **`GET /api/v1/system/status` 新增字段**（S2/S6）
  - `db_type`：运行时动态读取（如 `sqlite` / `postgresql`），替换原硬编码"PostgreSQL 16"
  - `model_info`：`{ name, status, demo_mode, signal_threshold, ... }`，`status` ∈ `loaded / synthetic_baseline / unavailable`

### 既有接口行为变更
- **`POST /api/v1/backtest/run`**（S4）
  - 入参校验增强：`initial_capital>0`、`0≤commission_pct≤0.1`、`0<signal_threshold<1`；不合法返回 `code=422` 与中文错误串（不再抛裸 422 异常）
  - 响应 `summary` 新增 `benchmark_return_pct`（基于真实价格序列）、`data_mode`（`real`/`synthetic`）
  - 响应 `accuracy` 结构变更：由"单一 win_rate"改为 `{ overall_7d, overall_30d, bullish_accuracy, bearish_accuracy, neutral_accuracy, sample_7d, sample_30d, sample_bullish, sample_bearish, data_mode }`
- **`GET /api/v1/news`**（S3）
  - 每条新闻 `url` 现为真实来源落地页（经 `migrate_002` 修正），供前端标题外链跳转
- **`GET /api/v1/stats/accuracy`**（S2/S4）
  - 响应新增样本量字段（见上），前端据此展示"样本偏小"提示

> 兼容性备注：所有响应仍包裹在 `{code,message,data}` 信封内；新增字段均带默认值，老前端缺省处理不报错。

## 5. 需人工确认 / 风险项

1. **真实回测路径仍基于 demo 种子信号**
   回测的"真实行情"路径（`data_mode="real"`）使用数据库内 `signals` 表信号，而这些信号的时间戳集中在 4 小时行情窗口内（demo 种子数据）。因此"真实"指价格序列真实、信号仍为演示种子；样本量与胜率在小样本下仅供参考。生产接入实时信号抓取后，本路径才具统计意义。

2. **`model_info` 显示 `synthetic_baseline`**
   `/status` 在 demo 模式下返回 `status="synthetic_baseline"`、名称"合成基线模型（演示）"。当前后端**无真实训练好的黄金预测模型**接入，S6 的"按真实情况呈现"指如实展示这一状态，而非虚构模型名。接入真实模型后需更新 `_model_info()` 与前端展示文案。

3. **无写类（CRUD）接口**
   数据源、模型配置目前均为**只读展示**（后端无写入/编辑端点）。若需在前端编辑数据源或模型参数，需另增 `POST/PUT` 接口与鉴权，属后续需求。

4. **新闻 URL 为来源分类落地页，非逐篇原文链接**
   `migrate_002` 把占位 URL 替换为对应来源的栏目/落地页（如路透债市、FRED、CBOE），并非每篇新闻的原文深链。因 demo 新闻无真实 article id，这是合理近似；若接入真实新闻抓取且带原始链接，可直接写入 `url` 覆盖。

5. **成本模型与基准的口径假设**
   回测成本 = 点差（价格单位）+ 名义金额 × 佣金率；基准 = 同期买入持有（`p1/p0-1`）。该口径为简化模型，不含滑点、隔夜利息、流动性冲击；与实盘存在偏差，结论仅作策略示意。

6. **`page-structure.md` 同步**
   本次已同步去除 F-code 与 `yfinance` 表述；但文档其余处（如 §5 接口映射）可能仍引用旧字段，已在本次一并修正 `benchmark_return_pct` 注释并补充 `data-sources` 行。如后续接口再变，需同步更新本文档与 `docs/联调测试结论.md`。

7. **依赖运行时状态**
   联调测试依赖后端进程（`uvicorn`，端口 8000）与已 seed 的 SQLite；CI/重跑前请先 `python -m app.core.seed` 确保数据存在，并确认后端以 `run_in_background` 方式常驻（避免被回收）。

## 8. 补充：新闻标题去方向化、呼应关键句（2026-08-06 二次优化）

> 需求：标题应以中文概括新闻核心内容、呼应对应关键句（key_sentence），**而非直接把多空方向（如"看多""看空""利好黄金""利空黄金"）作为标题**。
> 参考范例（保留）：`SPDR黄金ETF持仓量增加2.5吨，创近一个月新高`（对应关键句 *"Holdings rose to 945.3 tonnes, the highest in a month."*）。

### 8.1 问题
原规则生成器（`rule_summarize`）在标题末尾硬拼"利好黄金 / 利空黄金 / 影响中性"方向后缀，且以英文 `title` 为原料而非关键句，导致出现"黄金市场，看空黄金"这类把方向当标题的反模式。

### 8.2 改动
| 位置 | 改动 |
|------|------|
| `app/core/title_summary.py` | 删除 `_impact_phrase`（方向后缀）；`rule_summarize` 改为"主体 + 动作 + 数值 + 补充重点"，不再出现多空方向词；新增 `_detect_qualifier` 识别关键句中的"创近一个月新高 / 创两周新低 / 低于预期 / 高于预期 / 创纪录"等补充重点，使标题与关键句重点呼应；新增 `_detect_generic_subject` 兜底——对无法解析的英文标题提取专有主体（Meta / SpaceX / FBI 等），避免千篇一律的"黄金市场"；`_detect_subject` 对未知领域返回空交由兜底处理 |
| `app/core/title_summary.py`（`llm_summarize`） | 提示词改为：概括核心事实、呼应关键句，**禁止**用"看多/看空/利好黄金/利空黄金"作标题 |
| `app/core/sentiment.py` | LLM 提示词同步禁止方向式标题、要求呼应关键句 |
| `scripts/migrate_004_refine_title_zh.py` | 新增：幂等回填。仅对**英文标题**行重算 `title_zh`（这些才是含方向后缀的自动生成标题）；**中文标题**行（手工 demo 种子，含 §8 引用范例）保持不变，避免被规则产物覆盖 |

### 8.3 效果（DB 22 行）
- 12 行英文标题重算为"呼应内容/主体"的中文标题（如 `Meta AI 相关动态`、`SpaceX 相关动态`、`FBI Secretly Opened 相关动态`），**无任何"利好黄金/利空黄金/影响中性"残留**；

- **手工中文 demo 标题不重算**：为保证 §8 引用范例等高质量标题不被规则覆盖，迁移跳过中文标题行；若后续要全量用 LLM 重算，需另写脚本并显式覆盖。

## 9. 服务稳定性与中文标题旁路修复（第三轮，2026-08-10）

> 背景：对话 `启动服务，查看前端` 拉起的后台 uvicorn（`--reload`）进程在约 14m20s 后被系统 **`Killed: 9`**（SIGKILL）终止，前端无法访问；重启核查时发现实时爬虫入库的新闻标题仍为英文。本轮修复覆盖三方面：服务 OOM、爬虫直写旁路、LLM 凭据未复用。

### 9.1 服务 OOM 根因（`--reload` 递归监视）

- **现象**：`uvicorn app.main:app --reload` 跑约 14 分钟后进程被 SIGKILL。
- **根因**：`--reload` 依赖 WatchFiles **递归监视整个项目目录**，其中 `.venv_local/lib/python3.13/site-packages/`（streamlit / langchain / langgraph 等数千文件）被反复纳入监视，触发大量无意义 reload 并持续占用内存，最终 OOM 被杀。
- **修复**：
  - 重启时**不加 `--reload`**，服务恢复稳定（HTTP 200，已长期驻留）。
  - 新增 `scripts/start_backend.sh`：自动选用受管 venv、释放占用端口；并在注释中明确 **安全 reload 写法**：`--reload --reload-dir app --reload-dir frontend`，避免监视 `site-packages` 导致 OOM。
  - 已对脚本执行 `bash -n` 语法校验。

### 9.2 爬虫直写旁路（`news` 表缺 `title_zh`）

- **根因**：实时爬虫子项目 `news_scraper_llm/db.py::_get_or_create_news()` 直接以自有 ORM（`DbNews`）向共享 `news` 表插入 `title / content / source / url / published_at`，**不带 `title_zh`**，绕过了本应用的标题生成链；`serialize_news` 因此回退到英文 `title`。
- **修复**：在 `app/core/title_summary.py` 新增统一幂等接口 `backfill_missing_title_zh(db, limit=200) -> int`：
  - 仅对 **(1) 空、(2) 仍为英文、(3) 低质量规则回退**（"X 相关动态" 后缀、纯方向词）三类行重算 `title_zh`；
  - **中文非回退标题（含手工 demo 种子，如 §8 引用范例）一律跳过**，不会被覆盖；
  - 仅在 `settings.has_openai` 为真时才把低质量规则标题升级为 LLM 摘要。
- **挂载点**：`app/core/scheduler.py::_job_scrape_news()` 在爬虫子进程结束、刷新情绪因子**之前**调用该接口，实现"入库即补齐"。

### 9.3 LLM 凭据复用（应用层 `has_openai=False`）

- **根因**：OpenAI 兼容网关（阿里云百炼 `qwen-turbo`）凭据仅存在于 `news_scraper_llm/.env`，应用根目录无 `.env`，导致 `has_openai=False`、永久走规则回退，产出"黄金市场相关动态""下跌"等低质标题。
- **修复**：
  - `app/config.py` 新增 `openai_base_url` 字段与 `_load_scraper_llm_env()`；`get_settings()` 在应用层无 Key 时回退读取爬虫 `.env` 的 `OPENAI_API_KEY / MODEL / BASE_URL`（应用层 `.env`/环境变量始终优先，不重复存储密钥）。
  - `app/core/title_summary.py` 与 `app/core/sentiment.py` 的 `ChatOpenAI` 调用均透传 `base_url`。
  - 验证：`has_openai=True`、模型 `qwen-turbo`，对 "Billionaire diamond dealer's stunning fall" 返回 `亿万钻石商人因欺诈指控陷入困境`。

### 9.5 风险与说明

- **纯人名标题**：如只含人名的英文新闻，规则与 LLM 均难产出有效中文，保持英文为合理退化。
- **噪声新闻未治理**：爬虫入库的非黄金资讯（名人/火箭等）仅优化呈现，未做清洗删除（属数据治理专项，非本轮范围）。
