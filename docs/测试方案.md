## 0. 项目结构与技术栈识别结论（先对齐，再测试）

在编写任何用例之前，已对仓库做静态识别与一次全量冒烟，确认系统定位与边界如下。

### 0.1 系统定位

「点时成金」是一条**量化预测流水线**：多源数据采集 → 因子 / 特征工程 → 方向信号 → 可视化终端。核心交付物是对 **XAU/USD（黄金现货）30 分钟 K 线**的**涨跌方向**预测，并提供回测、新闻情感、鹰鸽指数、盈亏分布等辅助视图。

### 0.2 目录结构（关键路径）

```
forecasts for gold prices/
├── app/                      # 后端应用（FastAPI）
│   ├── main.py               # 入口：挂载 8 个 router + 托管前端 + /health
│   ├── config.py             # pydantic-settings 配置单例（含大写别名、派生属性）
│   ├── models/database.py    # SQLAlchemy 2.0 引擎（WAL + foreign_keys）、9 张表、SessionLocal、get_db
│   ├── api/                  # 路由层：signals / market / factors / news / backtest / stats / hawk_dove / system
│   ├── core/                 # 业务内核：predictor / scheduler / backtest / signal_generator / hawk_dove
│   │                         #          / data_quality / title_summary / sentiment_factor / feature_engineer / seed
│   └── pipeline/             # 爬虫落库小流水线：scraper / store / models
├── frontend/dashboard.html   # 单文件静态页（5 视图：dashboard / news / backtest / stats / settings）
├── tests/                    # 本方案落地的自动化测试
├── scripts/                  # run_tests.sh（一键执行）、frontend_integration_test.mjs（jsdom 回归）
├── data/                     # SQLite 数据库（gold_predictor.db，WAL 模式）
├── docs/                     # 本文档及验收模板
├── pytest.ini / .coveragerc  # 测试与覆盖率配置
└── requirements-test.txt     # 测试专用依赖（不含 lightgbm/xgboost/streamlit/playwright）
```

### 0.3 技术栈清单

| 分层 | 技术 | 说明 |
|------|------|------|
| Web 框架 | **FastAPI + Uvicorn** | 异步 API，12+ 端点，统一 JSON 信封返回 |

| 模型 | **LightGBM + XGBoost + scikit-learn** | 方向预测模型（joblib 落盘） |

| 测试 | **pytest / pytest-cov / pytest-html / pytest-timeout / pytest-xdist** | 见 §4 |
| 前端回归 | **jsdom（Node）** | scripts/frontend_integration_test.mjs（L2 方案，可选） |

## 1. 测试范围与目标

### 1.1 测试范围（In Scope）

- **单元层**：核心算法与纯函数（鹰鸽打分、标题概括、信号规则、回测参数解析、爬虫解析清洗、配置隔离）。
- **接口层（API）**：全部 13 个 `/api/v1` 端点的契约、健壮性（边界值、类型错误、分页、幂等、统一信封）、不变量。
- **集成层（数据与业务）**：数据库 schema 与约束、种子数据、数据质量、回测写库与读一致性、爬虫落库流水线。
- **端到端层（前端）**：dashboard.html 的 DOM 锚点、视图声明、接口同源、每个前端调用都能命中真实后端、字段存在性、文案合规、数据源 / 模型信息驱动。
- **性能基线**：只读接口 P95 SLA、回测耗时、并发稳定性、大 payload、因子 N+1 观测。
- **安全基线**：注入防护、路径穿越、无堆栈 / 密钥泄露、配置与 .gitignore 合规、上线前门禁项。

### 1.2 测试范围（Out of Scope / 标注 external）

- 真实外网爬虫（Playwright 浏览器二进制）—— 标记为 `external`，默认不执行，需外网 / Node 环境。
- 模型预测精度本身的统计学评估（属数据科学范畴，不在功能验收内）。
- 压测 / 混沌工程（本方案只做基线守门，非容量测试）。

### 1.3 测试目标

| 目标 | 度量 |
|------|------|
| 功能正确性 | 全量用例 0 失败（xfail 已知缺陷不计入失败） |
| 接口契约稳定 | 13 端点契约 100% 覆盖 |
| 数据一致性 | 回测读写一致、无孤儿外键、种子幂等 |
| 安全性红线 | 注入 / 穿越 / 泄露类用例 100% 通过 |
| 可验收性 | 覆盖率 ≥ 50%（demo 阶段基线），并提供 HTML 报告 + 覆盖率报告 |

### 2.2 测试隔离策略（关键，避免污染开发库）

`tests/conftest.py` 在导入 `app` **之前**注入以下环境变量，将测试流量重定向到独立库并关闭副作用：

```bash
DATABASE_URL=sqlite:///./.pytest_tmp/gold_test.db   # 隔离测试库，不碰 data/gold_predictor.db
DEMO_MODE=true                                      # 进入演示数据模式
SCHEDULER_ENABLED=false                             # 关闭后台调度
NEWS_SCRAPE_ENABLED=false                            # 关闭实时爬虫
```

> 约定：测试库位于 `.pytest_tmp/`，已在 `.gitignore` 中忽略。开发库 `data/gold_predictor.db` 不会被任何用例触碰。

### 2.3 依赖清单

- 运行时依赖：`requirements.txt`（FastAPI / SQLAlchemy / pydantic / pandas / numpy / beautifulsoup4 / lxml …）。
- 测试工具链：`requirements-test.txt`（pytest / pytest-cov / pytest-html / pytest-timeout / pytest-xdist / coverage）。
- 一键脚本 `scripts/run_tests.sh` 会在缺失时自动 `pip install -r requirements-test.txt`（幂等）。

## 3. 测试策略（分层、标记与优先级）

### 3.1 分层与 pytest 标记

所有用例通过 8 个自定义标记分层，支持按层运行与 CI 门禁：

`unit` · `api` · `integration` · `e2e` · `perf` · `security` · `slow` · `external`

> `external`（真实爬虫 / jsdom）默认被 `not external` 排除；`slow`（耗时基线）可按需单独跑。

### 3.2 优先级矩阵（取舍与优先级）

| 层级 | 优先级 | 占比 | 选取理由 | 取舍 |
|------|--------|------|----------|------|
| 单元（unit） | P0 | 高 | 核心算法一旦错，全盘错；最快、最稳定 | 必做，最先跑 |
| 接口健壮性（api） | P0 | 高 | 全部对外契约 + 边界 + 统一信封 | 必做，防回归 |
| 集成 / 数据（integration） | P0 | 高 | 数据库是系统真相源，回测一致性是核心 | 必做 |
| 端到端前端（e2e） | P1 | 中 | 无浏览器方案解析真实 HTML + 真后端校验，低成本高保真 | 必做（L1）；L2 jsdom 标记为 external |
| 性能基线（perf） | P2 | 中 | 只做 SLA 守门，阈值留 5~10 倍余量防假失败 | 基线即可，非压测 |
| 安全基线（security） | P0（红线）/ P1（门禁） | 高 | 红线必须过；上线门禁（鉴权/CORS/安全头/限流）以 xfail 固化待办 | 红线必过，门禁 xfail 跟踪 |

**优先级总原则**：正确性（单元+接口+集成）> 安全红线 > 端到端 > 性能基线 > 上线门禁（跟踪型）。

### 3.3 进入 / 退出标准

**进入标准（满足才可开始验收测试）**
1. `app` 可正常 `import`，`bash scripts/run_tests.sh install` 成功。
2. 开发库 `data/gold_predictor.db` 已存在且种子可加载（或测试能自建隔离库）。
3. 代码冻结（无正在进行的破坏性重构）。

**退出标准（满足才可签署验收）**
1. 全量 `all` 模式：**失败用例 = 0**（xfail 已知缺陷除外）。
2. 安全红线类（`SEC-01x`）100% 通过。
3. 覆盖率 ≥ 方案约定基线（当前实测 **58.32%**）。
4. `reports/` 下生成 `pytest-report.html` + `coverage.xml` + `summary.txt`。
5. 缺陷表（见验收模板）中所有 P0/P1 缺陷已闭环或书面确认遗留。

## 4. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 测试污染开发库 | 数据丢失 / 误改 | 环境变量隔离 + `.pytest_tmp/` + `.gitignore` |
| SQLite 秒级时间戳排序不确定 | 回测「取最新」取到旧记录（**已发现 DEF-001 并修复**） | 追加 `desc(id)` 次级排序键；用例 `test_latest_backtest_is_returned_by_read_apis` 固化回归 |
| 框架级 422 未包统一信封（DEF-002） | 前端错误处理不一致 | 用例 xfail 跟踪，待补中间件 |
| 非法日期被静默忽略（DEF-003） | 用户收到错误结论 | 用例 xfail 跟踪，待加校验 |
| 上线前缺鉴权 / CORS / 安全头 / 限流（DEF-004~007） | 安全暴露 | 安全门禁 xfail，明确「上线前必须」清单 |
| 路径含空格导致脚本拆分（**已修复 run_tests.sh**） | 一键脚本失效 | 引号包裹 `${PY}` 与版本命令 |
| 真实爬虫不稳定 | 用例抖动 | 标记 `external`，默认排除；用 fixture 解析替代 |
| 覆盖率偏低（采集 / 情感模块 ~22%） | 隐藏回归 | 在验收报告中如实披露，列低覆盖模块清单，作为后续补测 TODO |
